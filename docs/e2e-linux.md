# Linux validation scope

Three different kinds of evidence must remain distinct:

1. Integration and fault tests execute real Taskwarrior and SQLite with a controlled
   reviewer. They check authorization, generations, interruption, acknowledgment,
   stale forms, process recovery, undo, dependencies and transport boundaries.
2. Live Codex evaluations inspect actual structured responses and native state.
   Semantic review considers grounding, uncertainty, authorization and useful
   alternatives separately from the coordinator's decision to write or hold state.
3. A real Chromium pointer/keyboard traversal uses the real local service, Codex,
   Taskwarrior and SQLite. It exercises capture, persistent conversation, parallel
   fronts, a concrete capacity review, corrections, cancellation, snooze and undo.

The reminder system suite uses a private D-Bus receiver, new CLI processes and seven
accelerated logical days. It covers absences, backward clocks, restart, failed or
uncertain transport, budgets and stale claims. It does not validate physical suspend,
macOS delivery, corporate deployment or unattended schedules on a real desktop.

Initial failed traces and corrected reruns are kept separately in the private
architect run. They are not retroactively relabeled as successful. Local source
checks after the final review are not a second architect approval.
